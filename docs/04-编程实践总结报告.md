**问题 1: TypeScript 类型错误**

```
错误信息:
Type 'string | string[] | undefined' is not assignable to type 'string'

AI 建议的解决方案:
const noteId = Array.isArray(noteIdParam)
  ? noteIdParam[0]
  : noteIdParam || "";

解释: URL 参数可能是数组，需要处理这种情况
```

**问题 2: 自动保存性能优化**

```
问题描述:
用户每输入一个字符就触发保存，导致大量 API 请求

AI 建议:
使用防抖（debounce）机制，延迟 1 秒后再保存

实现:
const debouncedText = useDebounce(text, 1000);
useEffect(() => {
  if (debouncedText !== startingNoteText) {
    updateTextAction(noteId, debouncedText);
  }
}, [debouncedText]);
```

```
"App Router 是 Next.js 13+ 引入的新路由系统，
使用文件系统路由。每个文件夹代表一个路由段，
特殊文件 page.tsx 定义该路由的 UI。"

"Server Components 默认在服务器上渲染，
只需要添加 'use client' 指令才变为客户端组件。"

"Server Actions 是服务器函数，可以直接从
客户端组件调用，无需定义 API 路由。"
```

**效果**: 快速掌握了新技术栈，开发效率大幅提升。

#### 问题 2: TypeScript 类型问题

**描述**: 在处理 Next.js searchParams 时遇到类型错误。

**错误信息**:
```
Type 'string | string[] | undefined' is not assignable 
to type 'string'
```

**AI 提供的解决方案**:
```typescript
// 问题代码:
const noteId = searchParams.noteId; // 类型错误

// AI 建议的修复:
const noteIdParam = searchParams.noteId;
const noteId = Array.isArray(noteIdParam)
  ? noteIdParam[0]
  : noteIdParam || "";

// 解释: URL 参数可能是字符串、字符串数组或 undefined
// 需要处理所有情况
```

**收获**: 学会了如何正确处理 Next.js 的查询参数类型。

#### 问题 3: Prisma 客户端初始化

**描述**: 开发环境下 Prisma 客户端重复初始化导致警告。

**AI 诊断**:
```
问题原因:
Next.js 开发模式下热重载会导致模块重新加载，
每次都创建新的 Prisma Client 实例。

解决方案:
使用单例模式，将 Prisma Client 存储在全局变量中。
```

**实现**:
```typescript
import { PrismaClient } from '@prisma/client';

const globalForPrisma = global as unknown as {
  prisma: PrismaClient | undefined;
};

export const prisma = globalForPrisma.prisma ?? new PrismaClient();

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma;
}
```

**效果**: 完美解决了警告问题。

尽管 AIGC 工具非常强大，但也存在一些局限性：

#### 局限性 1: 代码理解的上下文限制

**问题**: AI 有时无法完全理解复杂项目的整体架构。

**表现**:
- 建议的代码可能与项目约定不一致

- 在提问时提供充分的上下文
- 明确说明项目规范和约定

#### 局限性 2: 新技术的知识滞后

**问题**: AI 的训练数据可能不包含最新的技术版本。

**表现**:
- Next.js 15 的某些新特性 AI 可能不了解
- 可能提供过时的实现方案
- API 变更可能导致建议的代码无法运行

**应对策略**:
- 查阅官方文档验证 AI 的建议
- 使用最新的 AI 模型（如 GPT-4）
- 结合官方示例和 AI 建议

#### 局限性 3: 创造性和判断力

**问题**: AI 缺乏真正的创造力和商业判断。

**表现**:
- 产品功能设计需要人工决策
- UI/UX 细节需要人工优化
- 商业逻辑需要深入思考

**应对策略**:
- 把 AI 作为辅助工具而非决策者
- 核心设计和关键决策由人类完成
- AI 负责实现细节和重复性工作

#### 局限性 4: 安全和隐私考虑

**问题**: 使用 AI 工具可能涉及代码泄露风险。

**应对策略**:
- 不向 AI 透露敏感信息（密钥、密码等）
- 使用环境变量管理机密信息
- 审查 AI 生成的代码是否有安全漏洞
